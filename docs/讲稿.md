## P1 · 封面（20 秒）

各位老师、同学好。

这次汇报的项目是**图片目标检索**：给一个装满各种图片的文件夹，自动挑出里面
含有某个特定标识的那几张，并且在图上把它的位置框出来。

技术上做了两条路线——一条不需要训练的 SIFT 特征匹配，一条可训练的 CNN 二分类，
最后对比了两者各自的能力边界。

---

## P2 · 问题定义（1 分钟）

先把任务说清楚：**这不是「识别这是什么」，而是「在一堆无关图片里，把它挑出来」。**

三件事：

- **输入**：一个文件夹，几百到几万张图，混着风景、海报、截图、二维码；
- **要找的**：一个固定图案，比如校徽、公司 logo、某个标识。它可能被旋转、
  被压缩、被贴在海报角落只有 90 像素宽；
- **输出**：命中的图片列表，**并且要框出位置**。

难点在哪？同一张图，可能被缩到 80 像素藏在角落，也可能被旋转 30 度、压成
低质量 JPEG。目标本身是固定图案，但背景千变万化——所以不能靠"像不像照片"
来判断，只能靠**图案本身的局部纹理**。

而且我们要的是**位置**，不只是"有没有"。

---

## P3 · 两条技术路线（1 分钟）

针对这个任务，我实现并对比了两套方案。

**左边是 SIFT 特征匹配**：不需要训练，只要一张模板图。它能直接框出位置，
对旋转缩放天然不变，换一个目标只要换一张模板图。代价是慢——纯 CPU 运算，
每张 300 多毫秒。

**右边是 CNN 二分类**：需要训练，但训练只要十几秒。它只回答"有还是没有"，
不告诉你位置。速度极快，GPU 上 3 毫秒一张。换目标就要重新训练。

我一开始的想法很自然：**CNN 先粗筛、SIFT 再精定位**——快的过滤掉大部分，
慢的只处理可疑的。这个组合在纸面上非常漂亮。

但第 11 页会告诉大家，这个想法在我们的场景里**没有走通**，以及为什么。

---

## P4 · SIFT 五步流程（1 分 40 秒）

SIFT 这套流程是项目的主线，分五步。

**第一步，模板特征。** 从一张干净的目标图里提取 SIFT 关键点和描述子。
关键点是图像里"有辨识度"的位置——角点、边缘拐弯处；描述子是这个点周围
一小块区域的纹理"指纹"，128 维向量。一张校徽能提出 2000 多个这样的指纹。

**第二步，多尺度提取。** 待检图在三个尺度上各提取一次：原尺寸、放大 1.7 倍、
放大 2.6 倍。为什么要放大？因为目标可能只有 90 像素宽，在原图上提不出足够的
关键点，放大之后细节才够。

**第三步，匹配筛选。** 用 FLANN 做最近邻匹配，每个模板点找两个最像的图上的点，
然后只保留"第一个明显比第二个像"的——这就是 Lowe ratio，阈值取 0.72。
这一步能甩掉大量似是而非的匹配。

**第四步，单应性估计。** 剩下的匹配点里还是有错的。用 RANSAC 求一个 3×3 的
变换矩阵，它描述"模板平面怎么旋转缩放平移到图上"。RANSAC 的做法是反复随机
抽几对点算矩阵，看有多少点符合——符合的点叫**内点**，不符合的叫外点。
抽足够多次，取内点最多的那个矩阵。

**第五步，几何校验。** 只有内点数够多（≥12）、内点占匹配数的比例够高（≥26%）、
投影出来的框长宽比合理，才判定命中。

**为什么这套流程不需要训练？** 因为 SIFT 描述子本身对旋转、尺度、光照就不变，
模板和待检图可以直接比对；RANSAC 又保证了只有位置关系自洽的匹配才算数。
零散的误匹配会被直接淘汰。

代价也很明确：**SIFT 是纯 CPU 的稠密运算，没有 GPU 实现**，而且对极小目标敏感。

## P5 · 模板制作（50 秒）

模板质量直接决定上限。

流程是：白底阈值分割、取最大连通域、自动裁出图案；然后放大 2.2 倍，再做
**反锐化掩模**提升边缘对比。

为什么要锐化？因为官方给的是 JPEG，边缘很软。不锐化的话，关键点数量会少一半，
小尺寸目标的召回会明显下降。

左边这张图是模板和它的关键点可视化——可以看到关键点集中在盾形轮廓、
中间徽标、文字这些高对比区域，这正是我们想要的。

最终模板 337×436 像素，2072 个关键点。

## P6 · 三组数据（50 秒）

我准备了三组数据，各管一件事。

**合成评测集，70 张**：40 张正样本、30 张负样本。正样本是把目标贴到不同背景上，
带旋转 ±35 度、透视变形、缩放 12% 到 55%、模糊、JPEG 压缩。
**它能精确控制变量**——我知道它是在哪一档开始失效的。

**真实素材集，58 张**：从学校官网抓的新闻图、海报、校园照、二维码。
**它不可控但真实**——用来验证结论不是合成数据上的自嗨。

**二分类训练池，2400 张**：给 CNN 用的，贴目标的局部块 1200 张 + 随机块 1200 张。

这里有个细节值得说：负样本里我**故意放了最容易混淆的东西**——同一套视觉体系的
周年标识，同样的红色、同样的校名文字、同样的轮廓。就是要看它会不会误报。

## P7 · 主结果（1 分 20 秒）

这是合成集上的结果：**召回 100%，精确率 100%，零漏检零误报。**

上面这张网格图，绿色框是正确检出，橙色是漏检，红色是误报——这一页没有错例。

可以看到目标在各种背景下都被准确框出来了：纯色底、纹理底、渐变底、
旋转过的、斜的、藏在风景照里的。

**但我更想强调这个 100% 是怎么来的**——不是手调的，是搜出来的。

## P8 · 参数网格搜索（50 秒）

三个关键参数：ratio 阈值、内点数量下限、内点比例下限。我在三维空间里扫了 27 组。

看这张表：ratio 放宽到 0.78，误报开始出现；收紧到 0.72，召回最稳。
而内点阈值从 9 提到 11，就把唯一的那个误报消掉了。

**有意思的是：只提了 2 个内点，误报就没了。** 说明误报和正例的内点数本身
是有区分度的，只是刚好卡在边界上。

最终取 ratio=0.72、内点≥12、内点比例≥26%，**在留出余量的同时保持 100%**。

## P9 · 真实素材验证（1 分钟）

合成集的 100% 不能说明全部问题，所以我又在真实图片上验了一遍。

58 张真实图片，8 张含目标。几个典型例子：

- **会议海报**：目标藏在一排 8 个合作 logo 的第 3 个，尺寸大约 90×115 像素；
- **周年活动图**：目标在左上角，和同体系的周年标识并排出现；
- **二维码图**：目标嵌在二维码中央，被严重遮挡；
- **校园风景、纯色底图、纹理背景**：全部正确排除。

另外单独做了 5 张标准素材的单张验证，5 张全部判断正确。

**这组数据说明：方法在真实场景是可用的**，不只是合成数据上好看。

## P10 · CNN 训练页（1 分钟）

第二条路线是 CNN 二分类。我把它做成了网页上可交互的形式。

左边六个参数可以拖：每类样本数、训练轮数、学习率、批大小、增强强度、
输入尺寸。点"开始训练"，右边实时画出 loss 和验证准确率的曲线，
跑完给出测试准确率、精确率、召回率。

默认配置——每类 600 张、14 轮——在 RTX 5070 上**13 秒**跑完，
测试准确率 **96.5%**，召回 99.3%。

这个页面本身也是个教学工具：比如把每类样本数拖到 100，准确率会直接崩到 55%，
召回 0——等于全判"没有"。把学习率压到 1e-4，只有 81%。

## P11 · 关键发现：CNN 粗筛走不通（1 分 40 秒）

这一页是整场汇报我最想讲的。

原本的设想是：**CNN 用 3 毫秒粗筛，通过的再交给 SIFT 精定位**。这样大部分图片
3 毫秒就排除了，整体能快十倍以上。

但实测数据显示，**CNN 在整图上的召回只有 57%**。

看这张表：周年活动图 4 张，目标占画面比较大，模型给 0.901，判断正确。
但会议海报——目标只占画面 3%——只有 0.187，漏检。
校园活动图目标在角落，0.108，漏检。小尺寸目标更是只有 0.014。
反过来，一张**不含目标**的红底周年图，模型给了 0.963，误报。

**为什么？** 根因很清楚：训练集的正样本是"紧贴目标裁下来的局部块"，
目标占画面 30% 到 60%；但推理时整图缩到 96×96，目标只占 3% 到 5%。
**训练分布和推理分布不一致**——模型学的是"画面里有一大块这个图案"，
而不是"画面某处藏了一个小图案"。

要救它得改成**滑窗推理**：把图切成 96×96 的块，批量送 GPU 推理。
那是另一个量级的工程——要处理几万块的调度、要重新设计正样本比例、
要做后处理合并框。

**所以这个项目最终没有采用"CNN 粗筛"这条路。**

我把这个负结果放在汇报里，是因为它比"我又实现了一个模块"更有信息量：
**一个方案在纸面上漂亮，不代表它在真实数据分布下能工作。**

## P12 · 三个提速决定（1 分 10 秒）

三个把速度做上去的决定，都是踩坑踩出来的。

**第一，纯 CPU 任务要用多进程，不是 GPU。**
SIFT 在 OpenCV 里没有 CUDA 实现，而它本身是单线程的——你 32 个核只用了 1 个。
改成 8 进程之后，118 张图从 118 秒降到 39 秒，**3 倍加速**，命中数完全一致。

**第二，`nfeatures` 必须设成 0，也就是不限。**
这个坑很隐蔽：设成 3000 的时候，SIFT 会按响应值截断关键点。在并列响应值上
取舍不稳定，同一张图在主进程和子进程里内点数能差 5 到 10 个，边缘样本的判定
就会翻转。表现就是"单进程和多进程结果不一样"。改成不限之后，1 进程和 8 进程
的结果完全对齐。

**第三，中间图片别过度压缩。**
示例图存成 JPEG quality 88 的时候，7 张含目标的图有 4 张掉到内点阈值以下被漏检；
换成 quality 97 后全部检出。**压缩损失的是细节，而特征匹配吃的就是细节。**

结论：这个任务的瓶颈是**特征匹配的纯 CPU 运算，不是 GPU 算力**。
加多进程比折腾 GPU 收益大得多。

## P13 · 产品形态（40 秒）

最终做成一个本地网页工具，两个页面。

**扫描页**：填文件夹路径，逐张检测，命中的排前面、绿框标位置。

**训练页**：就是刚才那六个滑块加实时曲线。

另外还有命令行版本，支持批量扫描、输出 CSV、画标注图、裁剪目标。

**最大的工程价值是"可替换"**：换一个目标，只需替换 assets 里的模板图，
代码零改动。

## P16 · 局限与下一步（50 秒）

说几个已知的局限：

**极小目标**：小于 40 像素容易漏，需要加大上采样尺度。
**单色剪影**：纹理丢了，需要额外做一版剪影模板。
**严重遮挡**：挡掉一半以上会漏，需要降低内点阈值、接受更多误检。

下一步三个方向：滑窗 CNN（重新设计正样本比例）、多模板融合、批量工具化。

**最重要的局限是：评测集是合成的。** 真实图库的分布更杂，上线前建议先用几百张
真实图确认阈值。

# 附录 A · 专业名词解释

> 按 PPT 出现顺序排列。**加粗**的是最可能被问到的。

| 名词 | 一句话解释 | 在本项目里的具体含义 |
|---|---|---|
| **SIFT** | Scale-Invariant Feature Transform，尺度不变特征变换。一种手工设计的图像特征提取算法，对旋转、缩放、亮度变化不敏感 | 整个检测器的核心。模板和目标图都提 SIFT 特征，然后比对 |
| **关键点（keypoint）** | 图像里"有辨识度"的位置：角点、边缘拐弯、纹理突变处 | 一张校徽模板能提出 2072 个关键点 |
| **描述子（descriptor）** | 关键点周围一小块区域的"纹理指纹"，通常是一个向量。两个描述子越接近，说明两处纹理越像 | SIFT 描述子是 128 维浮点向量 |
| **尺度空间 / 多尺度** | 同一个图案在不同放大倍率下看，会呈现不同的特征。多尺度就是准备多个放大倍率的版本 | 待检图在 1.0×、1.7×、2.6× 三个尺度上各提一次特征 |
| **Lowe ratio test** | 匹配时，每个特征点找最近的两个候选，如果"第一名"比"第二名"明显更像（距离小于第二名的 0.72 倍），才认这个匹配。用来过滤模棱两可的匹配 | 阈值 0.72 是网格搜索选出来的 |
| **FLANN** | Fast Library for Approximate Nearest Neighbors，快速近似最近邻库。在几百万个向量里快速找"最像的几个" | 用来做模板描述子和图片描述子之间的匹配 |
| **KNN 匹配** | K-Nearest Neighbors，找最近的 K 个。这里 K=2，就是每个点找两个最像的 | 配合 ratio test 使用 |
| **单应性矩阵（Homography）** | 一个 3×3 矩阵，描述"一个平面怎么变换成另一个平面"——包含旋转、缩放、平移、透视。8 个自由度 | 用来把模板的四个角投影到待检图上，从而得到目标框 |
| **RANSAC** | Random Sample Consensus，随机抽样一致。一种抗噪声的拟合方法：反复随机抽最少的点算模型，统计有多少点符合，取符合最多的那个 | 用来从一堆（有错的）匹配点里求出正确的单应性矩阵 |
| **内点 / 外点（inlier / outlier）** | 符合模型的数据点叫内点，不符合的叫外点（噪声、误匹配） | 我们的判定核心指标：内点数 ≥12 才算命中 |
| **内点比例** | 内点数 ÷ 参与拟合的匹配总数。反映匹配的"纯净度" | 要求 ≥26%，防止一堆乱匹配碰巧凑出一个矩阵 |
| **重投影误差** | 用求出的变换矩阵把点投影回去，和实际位置的偏差。RANSAC 用它判断"算不算内点" | 阈值 5 像素 |
| **IoU** | Intersection over Union，交并比。两个框的重叠面积 ÷ 合并面积，衡量"框得准不准"。≥0.5 通常算检测正确 | 评测时用 IoU≥0.25 作为"框对了"的标准（因为目标小，标准放宽） |
| **召回率（Recall）** | 真正有目标的图片里，被找出来的比例。**漏了多少** | 100% = 一张没漏 |
| **精确率（Precision）** | 被判为"有目标"的图片里，真的有目标的比例。**误报多少** | 100% = 一张没错报 |
| **F1** | 精确率和召回率的调和平均，一个综合指标 | 网格搜索就是按 F1 排序选参数的 |
| **正样本 / 负样本** | 正样本 = 含目标的图；负样本 = 不含目标的图 | 评测集 40 正 30 负；训练池各 1200 张 |
| **数据增强** | 人为地对训练图做变换（旋转、缩放、调色、擦除），让模型见过更多变化，减少过拟合 | 训练页的"增强强度"滑块控制这个 |
| **连通域** | 图像里连成一片的像素区域。取最大连通域 = 找到最大的那个图形块 | 用来从白底图里自动裁出模板 |
| **反锐化掩模（unsharp mask）** | 一种锐化方法：原图减去模糊版得到一个"边缘图"，再加回原图，边缘就变清晰了 | 提升模板边缘对比，让 SIFT 能提出更多关键点 |
| **多进程 / 并行** | 同时开多个进程分摊任务。Python 的 GIL 让多线程跑不满多核 CPU，所以计算密集型任务要用多进程 | 8 进程扫描，118 张从 118 秒降到 39 秒 |
| **GIL** | Global Interpreter Lock，Python 的全局解释器锁。同一时刻只允许一个线程执行 Python 字节码，所以多线程无法利用多核做计算 | 这是为什么用多进程而不是多线程 |
| **CNN** | Convolutional Neural Network，卷积神经网络。能自动从图像里学特征的网络结构 | 二分类方案用它判断"有没有目标" |
| **BN（BatchNorm）** | 批归一化。把每层输出标准化，让训练更稳更快 | 小数据微调时通常固定它，避免统计量被带偏 |
| **OneCycleLR** | 一种学习率调度策略：先升后降，中途达到最大值。比固定学习率收敛更快 | 训练页用的就是这个 |
| **训练分布 / 推理分布** | 训练时喂给模型的数据是什么样子，推理时实际遇到的数据是什么样子。两者不一致，模型就会失效 | 第 11 页那个失败方案的根因 |
| **滑窗推理（sliding window）** | 把大图切成很多小块，逐块送模型判断，再合并结果。用来检测"大图里的小目标" | CNN 粗筛方案要救活就得改成这样 |

# 附录 B · 可能被问到的问题

**Q1：为什么不用 YOLO / 目标检测网络？**
目标检测网络需要几百张**带标注框**的训练图，而且换一个 logo 就得重新标、重新训。
我们的场景是"目标固定、图库很大"，用特征匹配更划算——换目标只换一张模板图。

**Q2：合成评测集 100%，真实场景也能 100% 吗？**
不能保证。合成集只能证明算法在这些变换下不失效；真实集 8/8 检出只能说明
"可用"，不能说明"完美"。上线前应该用几百张真实图确认阈值。

**Q3：为什么内点阈值是 12 而不是 10 或 15？**
网格搜索的结果。11 就能消掉唯一误报，取 12 是留一点余量。
再往上会开始伤召回。

**Q4：CNN 那部分是不是白做了？**
不是。它的价值在于**证明了这条路在当前数据分布下不可行**，而且给出了明确的
修复方向（滑窗 + 重新设计正样本比例）。如果没做这个对比，我们可能会一直在
"SIFT 太慢"这个问题上打转，而不知道有更快的方案、也不知道它为什么不行。

**Q5：能不能同时找多个不同的 logo？**
当前是单模板设计。多模板要改判定逻辑：每个模板各跑一遍，然后做 NMS
（非极大值抑制）合并重叠框。工作量中等。

**Q6：SIFT 是专利算法吗？**
SIFT 的专利在 2020 年已经过期，OpenCV 4.x 把它放进了主模块（以前在
contrib 的 xfeatures2d 里）。可以自由商用。

**Q7：为什么扫描不用 GPU？**
SIFT 在 OpenCV 里没有 CUDA 实现，CUDA 模块只有 FAST、ORB 这一档。
而且真正的瓶颈是"单线程只用 1 个核"，多进程比 GPU 更直接有效。

**Q8：这个项目最难的部分是什么？**
不是写检测器，是**搞清楚"为什么结果不稳定"**。nfeatures 那个坑花了不少时间——
单进程和多进程结果不一致，最后定位到是特征点数量上限导致的取舍不稳定。
